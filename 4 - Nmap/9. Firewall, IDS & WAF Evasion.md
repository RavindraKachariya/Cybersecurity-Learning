# 9. Firewall, IDS & WAF Evasion

# **Firewall Evasion Techniques –**

Firewalls and intrusion prevention systems are designed to **block or confuse scanning tools like Nmap** so attackers cannot clearly see what services are running.

Because of this, Nmap provides **built-in evasion features** that help:

- Reduce detection
- Confuse security devices
- Test how strong the defensive controls really are

This section explains **all firewall evasion techniques available in Nmap**, one by one.

---

## **Fragment Packets (`f`)**

### **What this option does**

- The `f` option tells Nmap to **split scan probes into very small 8-byte packets**.
- Instead of sending one complete packet, Nmap sends many tiny fragments.
- Some old or poorly configured firewalls fail to properly inspect fragmented packets.

### **Why it is used**

- To confuse basic packet inspection engines.
- To bypass firewalls that only analyze full packets.
- To test how well a firewall handles packet reassembly.

### **Command**

```bash
nmap -f 10.10.1.48
```

### **Important Note**

- This option is **not very useful in modern networks**.
- It mainly works against **older or misconfigured firewalls**.

Some operating systems require `--send-eth` along with `-f` for fragments to work correctly.

---

## **Specify a Specific MTU (`-mtu`)**

### **What this option does**

- The `-mtu` option allows you to **manually define the packet size**.
- This also creates packet fragmentation, similar to `f`.
- The difference is that you control **how large each fragment is**.

### **Why it is used**

- To fine-tune fragmentation behavior.
- To test firewalls with different packet sizes.
- To evade devices that only inspect standard packet sizes.

### **Command**

```bash
nmap --mtu 16 10.10.1.48
```

### **Important Rules**

- MTU must be a **multiple of 8** (8, 16, 24, 32, etc).
- Very small MTU values create more fragments.

Some systems require `--send-eth` with `--mtu` for proper packet transmission.

---

## **Use a Decoy (`D`)**

### **What this option does**

- The `D` option sends scan traffic from **multiple fake IP addresses** along with the real scan.
- This makes it look like **many systems are scanning the target at once**.
- The real scanner hides among the decoys.

### **Why it is used**

- To hide the real scanning source.
- To confuse logs and alert systems.
- To slow down investigation and attribution.

### **Command (Random Decoys)**

```bash
nmap -D RND:10 10.10.1.48
```

### **Command (Manual Decoys)**

```bash
nmap -D decoy1,decoy2,decoy3 target
```

### **Warning**

- Too many decoys can **slow down the scan**.
- Some ISPs block spoofed traffic, reducing effectiveness.

---

## **Idle Zombie Scan (`sI`)**

### **What this option does**

- The idle scan uses a **third-party system (called a zombie)** to scan the target.
- Your system **does not directly send probes** to the target.
- The target believes the zombie is scanning it.

### **Why it is used**

- To hide the real scanner completely.
- To perform scans with **almost zero traceability**.
- To test firewall and IDS detection accuracy.

### **Command**

```bash
nmap -sI 10.10.1.41 10.10.1.252
```

### **Important Conditions**

- The zombie must be **idle**.
- It must use **predictable IP ID values**.
- If the zombie is active, the scan will fail.

 

Your system sends **no scan packets** to the target, except an optional initial ping.

## **Manually Specify a Source Port (`-source-port` / `g`)**

### **What this option does**

- Forces Nmap to use a **specific source port** for all packets.
- Some firewalls trust traffic from certain ports like DNS or FTP.
- This option exploits poorly written firewall rules.

### **Why it is used**

- To bypass port-based firewall rules.
- To make scan traffic look like trusted service traffic.
- To test firewall misconfigurations.

### **Command**

```bash
nmap --source-port 53 scanme.insecure.org
```

### **Shortcut Command**

```bash
nmap -g 53 scanme.insecure.org
```

### **Common Trusted Ports**

- 20 (FTP)
- 53 (DNS)
- 67 (DHCP)

---

## **Append Random Data (`-data-length`)**

### **What this option does**

- Adds **random padding data** to scan packets.
- Changes the packet size to avoid detection.
- Breaks predictable packet patterns.

### **Why it is used**

- Some firewalls look for known Nmap packet sizes.
- Random data helps evade such checks.
- Makes traffic less recognizable.

### **Command**

```bash
nmap --data-length 25 10.10.1.252
```

---

## **Randomize Target Scan Order (`-randomize-hosts`)**

### **What this option does**

- Changes the order in which targets are scanned.
- Prevents sequential scanning patterns.
- Makes detection harder.

### **Why it is used**

- Firewalls often detect **sequential IP scanning**.
- Random order appears less suspicious.
- Helps during large network scans.

### **Command**

```bash
nmap --randomize-hosts 10.10.1.100-254
```

---

## **Spoof MAC Address (`-spoof-mac`)**

### **What this option does**

- Changes the **MAC address** of your network interface.
- Prevents your real MAC address from being logged.
- Useful in local networks.

### **Command (Random MAC)**

```bash
nmap --spoof-mac 0 target
```

### **Command (Vendor MAC)**

```bash
nmap --spoof-mac Apple target
```

### **Command (Specific MAC)**

```bash
nmap --spoof-mac 00:11:22:33:44:55 target
```

---

## **Send Bad Checksums (`-badsum`)**

### **What this option does**

- Sends packets with **invalid checksums**.
- Properly configured systems drop these packets.
- Poorly configured systems may respond.

### **Why it is used**

- To test network stack correctness.
- To audit firewall and IDS behavior.
- To check for weak protocol handling.

### **Command**

```bash
nmap --badsum 10.10.1.41
```

Most modern systems **will not respond**, which is normal and expected.
