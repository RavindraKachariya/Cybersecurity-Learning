# 11. Troubleshooting & Debugging

# **Troubleshooting and Debugging – Overview**

---

Technical problems are a normal part of working with computers, and **Nmap is no exception**.

Sometimes a scan may:

- Not show the output you expected
- Throw an error
- Or produce **no output at all**

To handle such situations, Nmap provides **multiple troubleshooting and debugging options**.

These options help you **understand what is happening behind the scenes** and identify why a scan is failing or behaving unexpectedly.

This section explains all **troubleshooting and debugging features in Nmap**, one by one.

---

## **Getting Help (`h`)**

### **What this option does**

- Running `nmap -h` displays a **summary of all available Nmap options**.
- It shows scan types, target formats, and commonly used parameters.
- This is the quickest way to refresh your memory about Nmap syntax.

### **Command**

```bash
nmap -h

```

### **Additional Help**

- For detailed explanations, you can read the full Nmap manual using:

```bash
man nmap

```

### **Important Notes**

- The `man` command works on **Linux, Unix, and macOS** systems.
- Windows users can read the manual online at:
    - `www.nmap.org/book/man.html`

💡 **Tip:**

You can also get help by joining the Nmap mailing lists available at **seclists.org**.

---

## **Display Nmap Version (`V`)**

### **What this option does**

- The `V` option displays the **installed version of Nmap** on your system.
- This is very important when troubleshooting unexpected behavior.

### **Command**

```bash
nmap -V

```

### **Why this matters**

- Nmap is actively developed, and bugs are fixed frequently.
- Older versions may have:
    - Bugs
    - Missing features
    - Compatibility issues
- Always compare your version with the latest version available on **nmap.org**.

Running the latest version ensures:

- Better stability
- More features
- Fewer bugs

---

## **Verbose Output (`v`)**

### **What this option does**

- The `v` option enables **verbose output**.
- It shows **extra details** about what Nmap is doing during the scan.
- You can see each scan phase as it happens.

### **Command**

```bash
nmap -v scanme.insecure.org

```

### **Why it is useful**

- Helps troubleshoot **connectivity problems**.
- Shows progress when scans appear stuck.
- Helps you understand **how Nmap performs a scan internally**.

💡 **Tip:**

You can increase verbosity further by using:

```bash
-vv

```

---

## **Debugging (`d`)**

### **What this option does**

- The `d` option enables **debugging output**.
- It provides deep technical details about:
    - Timing
    - Packet sending
    - Retries
    - Internal scan logic

### **Command**

```bash
nmap -d scanme.insecure.org

```

### **Debug Levels**

- Debug levels range from **1 to 9**.
- Lower values = less output
- Higher values = very detailed output

Example:

```bash
nmap -d9 scanme.insecure.org

```

### **Why it is useful**

- Helps identify bugs.
- Useful when scans fail silently.
- Ideal for **advanced troubleshooting**.

---

## **Display Port State Reason Codes (`-reason`)**

### **What this option does**

- The `-reason` option shows **why Nmap marked a port as open, closed, or filtered**.
- It adds a “Reason” column to the scan output.

### **Command**

```bash
nmap --reason scanme.insecure.org

```

### **How to understand the output**

- `syn-ack` → Port is **open**
- `conn-refused` or `reset` → Port is **closed**
- No response → Port is **filtered (firewall)**

This option is very useful when you want to understand **firewall behavior**.

---

## **Only Display Open Ports (`-open`)**

### **What this option does**

- The `-open` option hides **closed and filtered ports**.
- Only ports in the **open** state are shown.

### **Command**

```bash
nmap --open scanme.insecure.org

```

### **Why it is useful**

- Makes output **clean and focused**.
- Helpful when scanning hosts with many closed ports.
- Saves time during analysis.

Without `--open`, Nmap shows all port states, which can clutter the output.

---

## **Trace Packets (`-packet-trace`)**

### **What this option does**

- The `-packet-trace` option shows **every packet sent and received** during a scan.
- It provides extremely detailed packet-level information.

### **Command**

```bash
nmap --packet-trace 10.10.1.1

```

### **Why it is useful**

- Helps debug **network connectivity issues**.
- Shows whether packets are being sent and received correctly.
- Useful for understanding firewall or routing problems.

💡 **Tip:**

Packet trace output scrolls very fast.

You can save it to a file using output options for easier review.

---

## **Display Host Networking Configuration (`-iflist`)**

### **What this option does**

- The `-iflist` option displays:
    - Network interfaces
    - IP addresses
    - MAC addresses
    - Routing table

### **Command**

```bash
nmap --iflist

```

### **Why it is useful**

- Helps identify which interfaces are active.
- Useful for troubleshooting routing issues.
- Quickly shows your system’s network setup.

💡 **Tip:**

Other useful networking commands:

- `ifconfig` (Linux/Unix)
- `ipconfig` (Windows)
- `netstat` (Most systems)

---

## **Specify Which Network Interface to Use (`e`)**

### **What this option does**

- The `e` option forces Nmap to use a **specific network interface**.
- This is important on systems with **multiple interfaces**.

### **Command**

```bash
nmap -e eth0 10.10.1.48

```

### **Why it is useful**

- Ensures traffic goes through the correct interface.
- Helpful on systems with:
    - Ethernet + Wi-Fi
    - Multiple network cards
- Prevents accidental scanning via the wrong network.
