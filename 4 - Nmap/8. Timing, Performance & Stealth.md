# 8. Timing, Performance & Stealth

## **What Are Timing Options in Nmap?**

- Timing options control **how fast or slow Nmap sends packets and waits for replies**.
- They help you **balance speed, accuracy, and stealth** depending on the network.
- You use them differently for:
    - Fast local networks
    - Slow internet scans
    - IDS/IPS-protected environments
    - Cloud systems with rate limits

 

**Timing options decide Nmap’s behavior, not just its speed.**

---

# **Timing Templates (`T0` to `T5`)**

### **Command**

```bash
nmap -T[0-5] target
```

### **Explanation**

- Timing templates are **predefined profiles** that adjust many timing settings at once.
- They save you from manually tuning every option.
- You choose them based on **how aggressive or stealthy** you want the scan to be.

### **Templates Meaning**

- `T0 (paranoid)` → Extremely slow, almost invisible
- `T1 (sneaky)` → Designed to avoid IDS
- `T2 (polite)` → Gentle, low impact
- `T3 (normal)` → Default and balanced
- `T4 (aggressive)` → Fast, good for LAN
- `T5 (insane)` → Very fast, very noisy

# **Time Value Formats (How Nmap Understands Time)**

- By default, Nmap treats time as **milliseconds**.
- You can also use:
    - `s` for seconds
    - `m` for minutes
    - `h` for hours
- All formats are equivalent if the value matches.

### **Examples**

```bash
nmap --host-timeout 300000 10.10.5.11
nmap --host-timeout 300s 10.10.5.11
nmap --host-timeout 5m 10.10.5.11
```

 

---

# **Minimum Parallel Operations (`-min-parallelism`)**

### **Command**

```bash
nmap --min-parallelism 100 target
```

### **Explanation**

- Forces Nmap to run **at least a fixed number of operations at the same time**.
- Useful on **fast, stable networks** where you want quicker results.
- Setting it too high can **overwhelm the network or cause inaccurate results**.

---

# **Maximum Parallel Operations (`-max-parallelism`)**

### **Command**

```bash
nmap --max-parallelism 1 target
```

### **Explanation**

- Limits how many scan operations can run simultaneously.
- Makes the scan **very slow but very gentle**.
- Useful when scanning **fragile systems or slow networks**.

---

# **Minimum Host Group Size (`-min-hostgroup`)**

### **Command**

```bash
nmap --min-hostgroup 30 10.10.1.0/24
```

### **Explanation**

- Controls how many hosts Nmap scans **in parallel** when scanning networks.
- Helps speed up **subnet or range scans**.
- Nmap will try not to scan fewer hosts than this number at once.

---

# **Maximum Host Group Size (`-max-hostgroup`)**

### **Command**

```bash
nmap --max-hostgroup 10 10.10.1.0/24
```

### **Explanation**

- Limits how many hosts are scanned together.
- Reduces **network load and IDS suspicion**.
- Useful when scanning sensitive environments.

---

# **Initial RTT Timeout (`-initial-rtt-timeout`)**

### **Command**

```bash
nmap --initial-rtt-timeout 5000 target
```

### **Explanation**

- RTT means **round-trip time** (send → reply).
- This sets how long Nmap waits **initially** for responses.
- Higher value = fewer retries, safer on slow networks.

---

# **Maximum RTT Timeout (`-max-rtt-timeout`)**

### **Command**

```bash
nmap --max-rtt-timeout 400 target
```

### **Explanation**

- Sets the **maximum waiting time** for packet responses.
- Lower values speed up scans but may miss slow replies.
- Higher values improve accuracy on unreliable networks.

---

# **Maximum Retries (`-max-retries`)**

### **Command**

```bash
nmap --max-retries 1 target
```

### **Explanation**

- Controls how many times Nmap retries when no response is received.
- Fewer retries = faster scan.
- More retries = more accurate but slower results.

---

# **Set Packet TTL (`-ttl`)**

### **Command**

```bash
nmap --ttl 500 target
```

### **Explanation**

- TTL controls how long packets stay alive in the network.
- Useful for **slow or long-distance connections**.
- Helps prevent packets from expiring too early.

---

# **Host Timeout (`-host-timeout`)**

### **Command**

```bash
nmap --host-timeout 1m target
```

### **Explanation**

- Forces Nmap to **stop scanning a host after a fixed time**.
- Prevents slow hosts from delaying the entire scan.
- Important for large internet or WAN scans.

 

---

# **Minimum Scan Delay (`-scan-delay`)**

### **Command**

```bash
nmap --scan-delay 5s target
```

### **Explanation**

- Forces Nmap to wait between probes.
- Useful against **rate limiting and IDS systems**.
- Makes the scan stealthy but significantly slower.

---

# **Maximum Scan Delay (`-max-scan-delay`)**

### **Command**

```bash
nmap --max-scan-delay 300 target
```

### **Explanation**

- Prevents Nmap from becoming **too slow** automatically.
- Keeps scan time under control.
- May reduce accuracy if set too low.

---

# **Minimum Packet Rate (`-min-rate`)**

### **Command**

```bash
nmap --min-rate 30 target
```

### **Explanation**

- Forces Nmap to send **at least X packets per second**.
- Useful for fast internal scans.
- High values can reduce accuracy.

---

# **Maximum Packet Rate (`-max-rate`)**

### **Command**

```bash
nmap --max-rate 30 target
```

### **Explanation**

- Limits how many packets are sent per second.
- Very useful for **IDS evasion and cloud rate limiting**.
- Slows scan but improves stealth.

💡 Tip:

```bash
--max-rate 0.1
```

→ One packet every 10 seconds.

---

# **Defeat Reset Rate Limits (`-defeat-rst-ratelimit`)**

### **Command**

```bash
nmap --defeat-rst-ratelimit target
```

### **Explanation**

- Some systems limit TCP RST packets to confuse scanners.
- This option attempts to bypass that behavior.
- Rarely needed and may reduce accuracy.
