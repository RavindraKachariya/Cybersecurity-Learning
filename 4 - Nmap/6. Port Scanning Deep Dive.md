# 6. Port Scanning Deep Dive

## Overview

This document provides a comprehensive guide to various port scanning techniques using Nmap, including their characteristics, use cases, and implementation details.

---

## TCP Connect Scan (`-sT`)

```bash
nmap -sT [target]
```

**Description:** Uses normal OS networking to complete a full TCP connection.

**Process:**
1. Connect to port
2. Connection established
3. Closed afterward

**Characteristics:**
- No admin privileges needed
- Easy but easily logged
- Slower than SYN scan

**When to use:**
- Admin/root access unavailable

**Concept:** Fully open the door, then close it.

---

## UDP Scan (`-sU`)

```bash
nmap -sU [target]
```

**Description:** Scans UDP ports instead of TCP.

**Behavior:**
- UDP has no handshake
- Often no response received
- ICMP error → port closed
- No response → open or filtered

**Characteristics:**
- Slow
- Less reliable

**Important for services like:**
- DNS
- SNMP

**Concept:** Send message and wait; silence is unclear.

---

## NULL Scan (`-sN`)

```bash
nmap -sN [target]
```

**Description:** Sends packets with no TCP flags set.

**Expected behavior:**
- Closed port → RST response
- Open port → no response

**Use case:** Bypass poorly configured firewalls

**Note:** Modern systems often detect or block it.

**Concept:** Send empty packet and observe reaction.

---

## FIN Scan (`-sF`)

```bash
nmap -sF [target]
```

**Description:** Sends packet with FIN flag.

**Response logic:**
- Closed → RST
- Open → no response

**Use case:** Sometimes bypasses simple filters

**Concept:** Send connection closing packet without opening.

---

## Xmas Scan (`-sX`)

```bash
nmap -sX [target]
```

**Description:** Packet sets FIN, PSH, and URG flags.

**Behavior:**
- Closed → RST
- Open → no response

**Use case:** Mostly used for firewall testing

**Concept:** Send strange packet and watch response.

---

## Custom Flag Scan (`--scanflags`)

```bash
nmap --scanflags [flags] [target]
```

**Description:** Allows manual selection of TCP flags.

**Use cases:**
- Advanced testing
- Firewall rule evaluation
- Research scans

**Concept:** Build your own probe packet.

---

## ACK Scan (`-sA`)

```bash
nmap -sA [target]
```

**Description:** Used to detect firewall rules.

**Important:** Does NOT detect open ports.

**Helps determine:**
- Filtered vs unfiltered ports
- Firewall presence

**Use case:** Firewall mapping

**Concept:** Check firewall behavior, not port status.

---

## IP Protocol Scan (`-sO`)

```bash
nmap -sO [target]
```

**Description:** Detects which IP protocols are supported.

**Example protocols:**
- TCP
- UDP
- ICMP
- GRE

**Use case:** Deep analysis

**Concept:** Discover supported network protocols.

---

## Ethernet vs IP Layer Sending

### Ethernet Layer (`--send-eth`)

```bash
nmap --send-eth [target]
```

**Description:** Sends packets directly via Ethernet

**Useful on:** Local networks

**Benefit:** Bypasses some OS routing layers

**Concept:** Send packets directly on local network.

### IP Layer (`--send-ip`)

```bash
nmap --send-ip [target]
```

**Description:** Forces Nmap to send packets via IP instead of Ethernet

**Use case:** When Ethernet sending isn't possible

**Concept:** Send packets via IP routing.

## Scan Type Reference Guide

| Goal | Scan Type |
|------|-----------|
| Normal scan | `-sT` |
| Fast stealth scan | `-sS` |
| UDP services | `-sU` |
| Firewall testing | `-sA` |
| Advanced flag behavior | `-sN`, `-sF`, `-sX` |
| Protocol discovery | `-sO` |

---

## Quick Command Reference

```bash
# TCP Connect Scan
nmap -sT target

# UDP Scan
nmap -sU target

# NULL Scan
nmap -sN target

# FIN Scan
nmap -sF target

# Xmas Scan
nmap -sX target

# Custom Flags Scan
nmap --scanflags FLAGS target

# ACK Scan
nmap -sA target

# IP Protocol Scan
nmap -sO target

# Ethernet Layer Send
nmap --send-eth target

# IP Layer Send
nmap --send-ip target
```

---

## Key Takeaways

1. **TCP Connect (`-sT`)** - Full TCP handshake, no root needed, easily logged
2. **UDP (`-sU`)** - Unreliable but important for UDP services
3. **Stealth Scans (`-sN`, `-sF`, `-sX`)** - Bypass simple firewalls
4. **ACK (`-sA`)** - Firewall mapping, not port detection
5. **IP Protocol (`-sO`)** - Protocol discovery
6. **Custom Flags** - Advanced research and testing

*Note: Always ensure you have proper authorization before performing any port scanning activities.*
