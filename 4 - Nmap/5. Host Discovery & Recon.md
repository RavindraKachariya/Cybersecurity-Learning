# 5. Host Discovery & Recon

# **Host Discovery Before Port Scanning**

Before scanning ports, Nmap first checks:

> Is the host even online?
> 

This step is called **host discovery**.

Scanning dead systems wastes time, so Nmap tries to detect live hosts first.

---

## How Nmap Checks if Host is Alive

By default, Nmap sends probes to see if the target responds.

Common methods include:

### ICMP Echo Request (Ping)

Nmap sends a ping request:

- If host replies → system is alive
- If no reply → host may be down or blocking ping

This is fastest method.

---

### TCP Port Check (80 & 443)

Since many firewalls block ICMP, Nmap also tries:

- Port 80 (HTTP)
- Port 443 (HTTPS)

Because web servers often allow traffic on these ports.

If host responds, Nmap assumes:

Host is alive.

---

## Why Default Discovery Sometimes Fails

Modern networks often block discovery probes.

Reasons:

- Firewalls block ICMP
- Servers drop unknown requests
- Cloud infrastructure filters probes
- Security devices hide system presence

Result:

Host appears offline even when alive.

---

## Problem During Secure Network Scans

In secured environments:

- Nmap may think hosts are down
- Port scanning may be skipped
- Real targets may be missed

So default discovery can slow or mislead scans.

---

## Why Alternative Discovery Methods Are Needed

Advanced discovery methods allow:

- Finding hidden hosts
- Scanning systems behind firewalls
- Discovering filtered or protected machines

Professionals adjust discovery techniques based on environment.

These commands control **how Nmap discovers live hosts before scanning ports**.

---

## `nmap -Pn [target]`

### Skip Host Discovery

Nmap assumes host is alive and directly starts port scanning.

Used when:

- Firewalls block discovery probes
- Host appears offline but is actually alive

**Concept:** Don’t check if host is alive, just scan.

---

## `nmap -sn [target]` *(Modern replacement of -sP)*

### Ping Scan Only (No Port Scan)

Checks which hosts are alive without scanning ports.

Used for:

- Discovering active devices in network

**Concept:** Find live hosts only.

---

## `nmap -PS[ports] [target]`

### TCP SYN Discovery

Sends SYN packets to specific ports.

If host replies → host is alive.

Works well when:

Web ports or services are open.

**Concept:** Knock using SYN packets.

---

## `nmap -PA[ports] [target]`

### TCP ACK Discovery

Uses ACK packets instead of SYN.

Useful when firewalls block SYN probes.

**Concept:** Detect host via ACK response.

---

## `nmap -PU[ports] [target]`

### UDP Discovery

Sends UDP packets to detect live hosts.

Used when:

UDP services are active.

Slower and less reliable.

**Concept:** Ask host via UDP traffic.

---

## `nmap -PY[ports] [target]`

### SCTP Discovery

Uses SCTP protocol instead of TCP/UDP.

Used in telecom or specialized networks.

**Concept:** Discovery using SCTP protocol.

---

## `nmap -PE [target]`

### ICMP Echo Request

Classic ping request.

Host replies → alive.

Often blocked by firewalls.

**Concept:** Standard ping discovery.

---

## `nmap -PP [target]`

### ICMP Timestamp Request

Uses timestamp request instead of ping.

Some systems reply even if echo blocked.

**Concept:** Alternate ping technique.

---

## `nmap -PM [target]`

### ICMP Address Mask Request

Older ICMP method; rarely used today.

Some legacy systems respond.

**Concept:** Legacy discovery method.

---

## `nmap -PO[protocols] [target]`

### IP Protocol Ping

Checks if host responds to specific protocols.

Used in advanced discovery cases.

**Concept:** Probe via protocol response.

---

## `nmap -PR [target]`

### ARP Discovery (Local Network)

Best method inside LAN.

ARP requests usually cannot be blocked.

Very accurate for local networks.

**Concept:** Ask local network directly.

---

## `nmap --traceroute [target]`

### Trace Network Path

Shows path packets take to reach target.

Useful for:

- Network mapping
- Finding routing paths

**Concept:** Map route to target.

---

## `nmap -R [target]`

### Always Resolve DNS Names

Forces DNS resolution for IP addresses.

Slower but useful in reports.

**Concept:** Convert IPs to domain names.

---

## `nmap -n [target]`

### Disable DNS Resolution

Prevents DNS lookups.

Makes scans faster.

Useful when DNS not needed.

**Concept:** Skip name resolution.

---

## `nmap --system-dns [target]`

### Use OS DNS Resolver

Uses operating system DNS instead of Nmap's internal resolver.

Helpful in restricted environments.

**Concept:** Let OS resolve DNS.

---

## `nmap --dns-servers [servers] [target]`

### Use Custom DNS Servers

Specify DNS servers manually.

Useful for:

- Bypassing local DNS restrictions

**Concept:** Choose DNS resolver manually.

---

## `nmap -sL [target]`

### List Targets Only

Shows targets without scanning them.

Used to verify targets before scan.

**Concept:** Preview targets list.
